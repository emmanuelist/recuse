The final case proves signature verification passes and the handler then
correctly declines to act on a folder id that does not exist, rather than
inventing a record.

Local unit verification of lib/foxit/webhook.ts:
  no secret configured   -> rejected (not_configured)   FAILS CLOSED
  correct signature      -> ACCEPTED
  wrong key              -> rejected (mismatch)
  tampered body          -> rejected (mismatch)
  missing signature      -> rejected (missing_signature)
  garbage / truncated    -> rejected (mismatch)

Event mapping: only folder_executed sets "signed". folder_completed stays
"pending" — parties having signed is not the same as the signature being
applied and the audit trail locked.
